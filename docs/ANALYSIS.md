# 기존 폰트 제작 프로그램 분석 — 장점 취합

조사한 프로그램 20여 개의 세부 내용과 출처는 아래 파일에 있다.
- [전문가용 편집기](research/01-pro-editors.md): Glyphs, FontLab, RoboFont, FontForge, FontCreator, BirdFont
- [웹·간편·매개변수형 도구](research/02-web-parametric-tools.md): Fontra, Glyphr Studio, FontStruct, Prototypo, Metaflop, Calligraphr, Fontself 등
- [한글·CJK 제작 방식](research/03-hangul-cjk.md): 벌수 체계, 제작사 공정, 명조·고딕 형태소, AI 생성 연구, 패키징 규격

> 공개 문서·논문·리뷰를 바탕으로 한 조사이며, 각 프로그램을 직접 써 보고 검증한 것은 아니다.

## 한눈에 보는 결론

1. **우리 방식(뼈대 + 스타일 엔진 + 자모 조합)은 업계 흐름과 맞다.**
   - FontLab(Power Stroke/Brush), Glyphs(Live Strokes, 스마트 컴포넌트), Fontark, Prototypo, StemFont 연구가 모두 같은 방향이다.
   - 다만 이 요소들을 **한글 11,172자 + 여러 스타일**에 한데 묶은 도구는 찾지 못했다.
2. **한글 조합은 "고정 배치 틀"에서 "규칙 표"로 바꿔야 한다.**
   - 업계 표준인 8×4×4벌(초성 8 · 중성 4 · 종성 4)에는 우리 12배치에 없는 문맥이 있다: ㄱ·ㅋ 뒤 모음, 모음별 받침, ㅜㅠ·ㅝ 계열 분리.
   - Glyphs도 규칙 기반 조합 그룹을 쓴다.
3. **명조·고딕·손글씨·붓글씨는 측정 가능한 형태소 매개변수로 나뉜다.**
   - 명조: 부리, 맺음, 꺾임, 꼭지이응, 굵기 대비
   - 손글씨: 흔들림, 탈네모
   - 붓글씨: 기필·행필·수필
   - 이 매개변수들을 스타일 엔진의 1급 설정으로 둔다.
4. **초보자에게는 "프리셋에서 시작 + 묶음별 슬라이더"가 가장 잘 먹힌다** (Prototypo, Metaflop). 전문가 기능은 켜야 보이게 한다 (FontStruct 전문가 모드).
5. **파일 품질은 규격에서 결정된다.** 반드시 지켜야 할 것:
   - 겹침 제거
   - 한국어 이름(0x0412)
   - OS/2 코드페이지·유니코드 범위 비트
   - em 상자 880/−120과 USE_TYPO_METRICS
   - 호환 자모 포함
6. **작업물이 서비스 종료로 사라지면 안 된다** (Prototypo·Fontark·온글잎의 교훈). 서버 없이 동작하고, 프로젝트 파일로 언제든 백업할 수 있어야 한다.

### 제외 (이유)
- **실시간 다인원 협업**(Fontra): 서버가 필요하다. 로컬 우선 원칙과 충돌.
- **픽셀 생성 AI**(DK-Font 등): 결과가 비트맵이라 품질 관리가 어렵다. 샘플로 매개변수를 맞추는 방식으로 대체.
- **수동 힌팅**: 11,000자 규모의 CJK 폰트는 보통 힌팅 없이 낸다.
- **컬러 폰트·OpenType 기능 편집기 전체**: 목적(범용 한글 글꼴)에 비해 우선순위가 낮다.
- **커뮤니티 갤러리**: 서버가 필요하다. 나중에 검토.
